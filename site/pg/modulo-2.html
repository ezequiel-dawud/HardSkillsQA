Módulo 2 — Tipos de verdade

boolean, numeric x divisão inteira, CAST/::, NULL, IS DISTINCT FROM

Antes de começar

O SQLite é frouxo com tipos: aceita ativo = 1, junta texto com número sem reclamar. O Postgres é rígido — e isso é bom, porque erro de tipo vira erro na hora, não dado torto que só aparece semanas depois.

  • boolean — ativo aqui é true/false, não 0/1. WHERE ativo já basta (é "onde ativo é verdadeiro"). O contrário é WHERE NOT ativo. Também existe ativo IS TRUE / IS FALSE / IS NOT TRUE (esse último pega inclusive NULL).
  • Divisão inteira. 5 / 2 dá 2 (dois inteiros → resultado inteiro). Pra ter 2.5: 5 / 2.0 ou 5::numeric / 2. Pega muita gente em cálculo de taxa/percentual.
  • CAST(x AS tipo) ou x::tipo — converte de propósito: '42'::int, preco::int, data_abertura::text.
  • NULL não é igual a nada, nem a outro NULL. Teste com IS NULL / IS NOT NULL. COALESCE(a, b) devolve o primeiro não-nulo. a IS DISTINCT FROM b compara tratando NULL como um valor comum (útil pra "mudou?").

Olhar de QA: "esse campo devia ser numérico e veio texto" ou "somaram 0/1 num campo boolean" são bugs clássicos — no Postgres o próprio banco te avisa.

Dois exemplos

Teoria

  • WHERE ativo — coluna boolean já é a condição. Negativo: WHERE NOT ativo.
  • coluna IS TRUE / IS FALSE / IS NOT TRUE — o IS NOT TRUE também casa com NULL.
  • 5 / 2 = 2 (inteiro). 5::numeric / 2 = 2.5. ROUND(x::numeric, 2) arredonda.
  • x::tipo = CAST(x AS tipo). Ex.: valor_total::int, '2025-01-01'::date.
  • COALESCE(a, b, …) — primeiro valor não-nulo. NULLIF(a, b) — vira NULL se a = b.
  • a IS DISTINCT FROM b — "são diferentes", contando NULL como valor.
