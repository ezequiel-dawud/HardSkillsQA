Módulo 1 — Primeira requisição

GET, status code, ok, corpo JSON, 200 × 404

Teoria

Uma chamada de API tem 3 coisas que a gente sempre olha:

  • Status code — número que resume o que aconteceu: 200 ok, 201 criado, 400 pedido malformado, 401/403 sem permissão, 404 não existe, 405 método errado, 500 a API quebrou.
  • Corpo (body) — normalmente JSON: um objeto ou uma lista.
  • Cabeçalhos — ex.: content-type: application/json.

Aqui você usa const r = await api('GET', '/caminho'). O r tem r.status, r.ok (true se 2xx), r.json (o corpo já convertido) e r.headers. Pra afirmar algo, check('rótulo', condição).

Área livre

Olhar de QA

Status code é a primeira camada, e sozinho já pega muita coisa — mas pare aqui e você terá uma suíte verde que não garante nada. O hábito que vale construir desde agora é testar o caminho de erro com o mesmo cuidado do caminho feliz: id inexistente, método errado, filtro sem resultado. O caminho feliz quase sempre já foi testado por quem escreveu a API. O que ninguém testou é o que acontece quando dá errado — e é lá que mora comportamento não especificado.
