Trilha Teste de API

HTTP, status codes, contrato da resposta, e o pulo do gato de QA: cruzar o que a API devolve com o que ficou gravado no banco.

Como a prática funciona aqui

Uma API falsa responde dentro da própria página — sem instalar nada, sem servidor. Nos exercícios você escreve um trecho de JavaScript que faz requisições com api('GET', '/produtos/3') e confere o resultado com check('status 200', r.status === 200). Também tem db — a base crua — pra comparar API × banco. A API tem 2 bugs plantados pra você achar.

Provas por módulo

Questões de múltipla escolha corrigidas na hora, mais uma questão aberta por prova — ela não entra na nota e existe pra você comparar o seu texto com uma resposta modelo. Nota ≥ 70% = módulo firme. Faça depois de estudar o módulo correspondente.

Referência rápida da API falsa

RequisiçãoResposta
GET /produtos200 — lista. Aceita ?categoria= e ?ativo=0|1
GET /produtos/:id200 — um produto; 404 se não existe
GET /clientes/:id · /clientes/:id/pedidos200 — cliente / pedidos dele
GET /pedidos · /pedidos/:id200 — lista (aceita ?status=) / um pedido
GET /defeitos200 — aceita ?severidade= e ?modulo=
POST /defeitos201 com o defeito criado; 400 se faltar titulo ou severidade
