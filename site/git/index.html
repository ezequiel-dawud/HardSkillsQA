Trilha Git e GitHub para QA

O mínimo de Git pra baixar o código, versionar seus testes, ler o que mudou num Pull Request e entender o vermelho do CI. Três módulos curtos, direto ao que se usa.

Por que esta trilha existe

As trilhas de pytest, k6 e CI/CD pedem clonar o repositório, criar branch, commitar e abrir Pull Request. Se você nunca fez isso, é aqui que se resolve — em cerca de duas horas no total, fazendo de verdade. Não precisa saber programar.

Módulos

Módulo 1
Por que Git existe, e pegar o código
o problema que ele resolve, Git × GitHub, vocabulário, instalar, fork e clone
Módulo 2
O ciclo do dia a dia
as três áreas, status/add/commit/push, branch, ler diff e log, conflitos sem pânico
Módulo 3
Pull Request e o papel do QA
abrir um PR, ler um diff com olhos de quem testa, os checks do CI

Provas por módulo

Múltipla escolha, corrigida na hora, com uma questão aberta por prova. Nota ≥ 70% = módulo firme.

Cola de comandos

# começar
git clone https://github.com/SEU-USUARIO/HardSkillsQA.git
cd HardSkillsQA

# antes de começar algo novo
git switch main
git pull
git switch -c nome-do-branch

# o ciclo
git status                       # onde estou / o que mudou
git diff                         # o que eu mudei, linha a linha
git add caminho/do/arquivo
git commit -m "mensagem que explica o que muda"
git push -u origin nome-do-branch

# investigar
git log --oneline -10            # últimos commits
git log --oneline -- trilha-3/   # commits que tocaram nessa pasta
git show a1b2c3d                 # o que aquele commit mudou
git restore arquivo              # desfaz edição não commitada (perde o que escreveu)
