Módulo 3: Cenários do site de treino

Login compartilhado entre testes, loading assíncrono, paginação, estado vazio, modal e upload de arquivo.

1. Reaproveitando a LoginPage do Módulo 1

/index.html, /produto.html e /carrinho.html exigem sessão: sem login, redirecionam pra /login.html. O Módulo 2 te ensinou Page Object Model; aqui está o primeiro pagamento desse investimento: em vez de reescrever o preenchimento do login, criamos pages/LoginPage.js (mesma ideia da CadastroPage) e reaproveitamos ela, o mesmo fluxo que o Módulo 1 já testou:

const { LoginPage } = require("../pages/LoginPage");

async function login(page) {
  const loginPage = new LoginPage(page);
  await loginPage.goto();
  await loginPage.login("maria@exemplo.com", "SenhaForte123");
  await expect(page).toHaveURL(/index\.html/);
}

test.describe("lista de produtos", () => {
  test.beforeEach(async ({ page }) => {
    await login(page);
  });
  // ...
});

O await expect(page).toHaveURL(...) no fim da função importa: o clique dispara um fetch com atraso proposital antes de redirecionar. Sem esperar a URL mudar, o próximo passo do teste pode rodar contra a tela de login ainda meio carregada.

2. Loading assíncrono, paginação e estado vazio

A lista de produtos também ganhou uma Page Object (pages/ProdutosPage.js). Ela busca os dados com um atraso proposital: dá pra testar o carregamento de verdade, não um "pisca" rápido demais pra reparar:

const produtos = new ProdutosPage(page);
await expect(produtos.produto(1)).toBeVisible();
await expect(produtos.loadingSpinner).toBeHidden();

A mesma página tem um parâmetro pra forçar lista vazia, sem precisar mexer no servidor, útil pra testar o estado vazio isoladamente. É por isso que ProdutosPage.goto() aceita uma opção:

await produtos.goto({ vazio: true }); // navega pra /index.html?vazio=1
await expect(produtos.emptyState).toBeVisible();

E a paginação é só clicar e conferir o número atual:

await produtos.paginationNext.click();
await expect(produtos.paginationCurrent).toHaveText("2");

3. Modal de confirmação

Ao adicionar um produto ao carrinho, um modal confirma. A ProdutoPage (pages/ProdutoPage.js) já espera o detalhe do produto carregar dentro do próprio goto(id). O botão "adicionar" não faz nada se o produto ainda não carregou (não há indicador disso na tela, vale anotar como melhoria de UX pra reportar), então esperar faz parte de "abrir a página" nessa classe, não algo que cada teste precisa lembrar de repetir:

const produto = new ProdutoPage(page);
await produto.goto(1); // ja espera o titulo carregar

await produto.addToCartButton.click();
await expect(produto.modalMessage).toContainText("foi adicionado");

4. Upload de arquivo

setInputFiles simula a escolha de um arquivo sem precisar abrir o seletor nativo do sistema operacional:

await produto.fileInput.setInputFiles(
  path.join(__dirname, "..", "fixtures", "exemplo.png")
);
await expect(produto.filePreview).toContainText("exemplo.png");

Funciona mesmo com o accept="image/*" do campo: esse atributo só filtra o que aparece no seletor manual, não bloqueia setInputFiles.

Olhar de QA

Repare que cada teste deste módulo espera por algo específico antes de agir (o título do produto não estar vazio, o spinner sumir). Nenhum usa sleep(). Isso não é estilo, é necessidade: o atraso artificial das APIs varia, e esperar "um tempo fixo" cedo demais produz teste instável (passa na sua máquina, falha na do colega ou no CI, que costuma ser mais lento). Esperar a condição certa em vez do tempo certo é o que separa teste de UI confiável de teste de UI que ninguém confia mais depois de algumas semanas.
