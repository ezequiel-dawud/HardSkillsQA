Trilha CI/CD para QA

Entender o que é um pipeline, ler um arquivo do GitHub Actions sem se assustar, e fazer os testes rodarem sozinhos a cada mudança — reprovando o build quando algo quebra.

Esta trilha é de leitura — e mexe no que já existe

Não tem nada rodando na página. O "laboratório" é o próprio repositório: ele já tem dois pipelines de verdade em .github/workflows/ (um da Trilha 3, um da Trilha 5). Você vai lê-los, entendê-los linha a linha e fazer pequenas mudanças.

Pré-requisito: ter o repositório no GitHub (o seu fork) e ter feito a Trilha 3 (pytest) — os exemplos usam aquele projeto. Não precisa instalar nada novo.

Provas por módulo

Questões de múltipla escolha corrigidas na hora, mais uma questão aberta por prova — ela não entra na nota e existe pra você comparar o seu texto com uma resposta modelo. Nota ≥ 70% = módulo firme. Faça depois de estudar o módulo correspondente.

Módulos

Módulo 1
O que é CI/CD, sem jargão
a analogia, o pipeline, o loop de feedback, o ✓ e o ✗ no Pull Request, por que QA ganha com isso
Módulo 2
Ler um pipeline linha a linha
o que é YAML, on, jobs, runs-on, steps, uses vs run — no arquivo real da Trilha 3
Módulo 3
Fazer o build reprovar
código de saída, o portão de qualidade, required checks no PR, o badge no README, quebrar um teste de propósito
Módulo 4
Um pouco além + o resto do mundo
matrix, cache, secrets, artefatos (guardar o relatório), agendamento; mapa rápido GitLab CI / Jenkins / Azure

Pré-requisito

Ter feito a Trilha 3 e ter o repositório no seu GitHub. Se você só baixou o ZIP, o Módulo 1 explica como colocar no GitHub — é de graça e leva dois minutos.
