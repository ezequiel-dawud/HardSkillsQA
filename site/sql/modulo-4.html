Módulo 4 — Juntar tabelas

INNER JOIN, LEFT JOIN, 3+ tabelas

Teoria

  • INNER JOIN b ON a.x = b.y — só as linhas que casam nas duas tabelas.
  • LEFT JOIN — todas as linhas da tabela da esquerda, mesmo sem par na direita (as colunas da direita vêm NULL).
  • Padrão pra achar "quem não tem": LEFT JOIN ... WHERE b.id IS NULL.
  • Sempre qualifique colunas que existem nas duas tabelas: pedidos.id, clientes.id. Apelidos deixam mais curto: FROM pedidos p JOIN clientes c ON c.id = p.cliente_id.
  • Dá pra encadear 3+ JOIN na mesma query.

Olhar de QA: os dados reais moram espalhados em várias tabelas. JOIN é o que reconstrói "o pedido inteiro" pra você conferir.

Exemplos de aplicação

Um exemplo montado pra cada item da teoria acima. Não precisa rodar — é pra ver a cara do recurso e entender cada pedaço. Os valores são ilustrativos.

INNER JOIN

SELECT pedidos.id,
       pedidos.valor_total,
       clientes.nome AS cliente
FROM pedidos
INNER JOIN clientes ON clientes.id = pedidos.cliente_id;

O pedido guarda só o cliente_id. O ON clientes.id = pedidos.cliente_id casa cada pedido com a linha do cliente que tem aquele id, e aí dá pra mostrar o nome junto. INNER: pedido sem cliente correspondente fica de fora.

LEFT JOIN

SELECT clientes.nome,
       pedidos.id AS pedido_id
FROM clientes
LEFT JOIN pedidos ON pedidos.cliente_id = clientes.id;

LEFT JOIN mantém todos os clientes, com pedido ou sem. Quem tem pedido aparece uma vez por pedido; quem não tem aparece uma vez, com pedido_id vindo NULL — não há linha de pedido pra preencher.

Achar "quem não tem"

SELECT clientes.id, clientes.nome
FROM clientes
LEFT JOIN pedidos ON pedidos.cliente_id = clientes.id
WHERE pedidos.id IS NULL;

O LEFT JOIN traz o cliente mesmo sem pedido (colunas de pedidos em NULL); o WHERE pedidos.id IS NULL mantém só essas linhas. Resultado: clientes que nunca compraram.

Qualificar colunas + apelidos

SELECT p.id,
       p.data_pedido,
       c.nome AS cliente,
       c.estado
FROM pedidos AS p
JOIN clientes AS c ON c.id = p.cliente_id
WHERE c.estado = 'SP';

id existe nas duas tabelas; escrever p.id / c.id evita ambiguidade. O apelido (pedidos AS p) encurta o resto. JOIN sozinho já é INNER JOIN.

Encadear 3+ JOIN

SELECT p.id AS pedido,
       c.nome AS cliente,
       pr.nome AS produto,
       ip.quantidade
FROM pedidos AS p
JOIN clientes AS c      ON c.id = p.cliente_id
JOIN itens_pedido AS ip ON ip.pedido_id = p.id
JOIN produtos AS pr     ON pr.id = ip.produto_id;

Cada JOIN liga mais uma tabela pela chave certa: pedido→cliente, pedido→itens, item→produto. Assim você remonta a compra inteira (quem comprou, o quê, quantas unidades) numa linha por item.
